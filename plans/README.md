## Resolved STOPs

- 005 hit its own STOP condition on Step 4's corpus edit: `corpus/vol2` has 29 real
  publisher figures shipped with `alt=""` (moesta-ch2, enns-qualifying, enns-value,
  enns-closing), past the plan's "~15 entries" ceiling for `alt_overrides`. Ruling:
  29 filler alt strings would be worse than an honest gap, so plan 005 shipped a
  source-level waiver (`source.images.alt_policy: "waived"` + `reason`) instead of
  per-image overrides. `alt_text` honors the waiver in draft mode only; `--release`
  ignores it and still fails on the 29 offenders, which is correct — real alt text is
  a release requirement. `corpus/vol2/manifest.json`'s four affected sources now carry
  the waiver. Real alt authoring via a vision-capable agent is queued as iteration-3
  work, not plan 005's.

- 006's E18 (a release build with a sidecar asserting `claims: []`) proved `check.py`'s
  `claims_ok` did not enforce its documented contract: it only flagged per-entry blank
  `claim`/`support` fields, and `any()` over an empty list is vacuously `False`, so a
  sidecar declaring zero claims passed the "claims" release gate. Fixed under plan
  006's gate-enforcement clause: `claims_ok` now requires a non-empty claims list
  before checking per-entry blanks. Covered by evals/run_evals.py E18 and
  tests/test_release_gates.py's `test_empty_claims_list_fails_release_claims_gate`.

- 011's Step 1 CSS audit found two real e-ink-safety issues (viewport units on
  `.fullpage`/`.cover img`; `h1,h2,h3` missing the legacy `page-break-after:avoid`
  alongside `break-after:avoid-page`) but did not apply either fix: both would change
  `quoin/assemble.py`'s `CSS` literal, which changes the default profile's packaged
  bytes and its corpus determinism hash — out of bounds per the plan's hard gate.
  Reported as a proposed (unapplied) diff to the plan owner instead of committed.

- 011's Step 2 first cut of `wrap_kobo_spans` broke EPUBCheck on real corpus content
  (`corpus/vol2`), the plan's own named STOP condition: pretty-printed markup puts
  whitespace-only text nodes directly inside `<ol>`/`<ul>`, between/around `<li>`
  siblings; wrapping those in `<span>` makes the span a direct child of `ol`/`ul`,
  which EPUB's content model only allows `li`/`script`/`template` inside (RSC-005).
  Fixed by leaving whitespace-only text nodes unwrapped (matches upstream kepubify
  behavior) rather than reported-and-left-broken, since the fix is confined to the
  kepub-only code path and touches no default-profile byte. Covered by
  `tests/test_kepub.py::test_whitespace_between_list_items_is_not_wrapped` and
  reverified against `corpus/vol2 --profile kepub` (EPUBCheck 0/0/0 after the fix).

- 013's owner ruled on 011's deferred CSS diff (see 011's Step 1 entry above): apply
  both fixes as a deliberate, one-time baseline change inside 013's own commit batch,
  since a versioned break recorded at an iteration boundary is what build records
  exist for. `quoin/assemble.py`'s `CSS` literal now sets `html,body{height:100%}`
  explicitly and uses percentage equivalents (`min-height:82%`, `max-height:100%`)
  in place of `82vh`/`100vh`, plus the legacy `page-break-after:avoid` fallback ahead
  of `break-after:avoid-page` on `h1,h2,h3`. This changed the default profile's
  packaged bytes exactly once. Corpus determinism baseline moved from `df281e14…`
  (recorded in `docs/ITERATION-2.md`) to `b0cfdb60bf51407e5547d3ee854f033f1b5b8a5d618dc49fa84a7e547c3177f1`,
  reverified stable across two independent cold `corpus/vol2` rebuilds; every other
  check row stayed PASS, none changed state.

- 013's fix 2 (`check.py` must rebuild before validating, not trust a stale target)
  needed one refinement past its literal wording. An unconditional
  `build(root, draft=not release, profile=profile)` call, wrapped in a bare
  `except QuoinError: pass`, silently gave up refreshing the target whenever a
  release build hit a genuinely missing block (`blocks.read_for_build` hard-fails
  in that case by design) — leaving the stale, pre-tamper artifact in place for
  every row below, which is exactly the defect this fix exists to close, and worse,
  it reproduces on precisely the incomplete books most likely to need it. Fixed by
  retrying once in draft mode (`build(root, draft=True, profile=profile)`, itself
  wrapped defensively, though `read_for_build`'s draft path never raises) purely to
  refresh `target` from current sources; block completeness stays the job of the
  existing "placeholders"/"stylepass"/"claims" rows, computed independently and
  always in draft mode. Verified both ways: an incomplete-blocks book with a
  tampered source now correctly fails `privacy`/`word_counts` instead of reading
  the stale zip as clean, and a complete-blocks release book still gets a
  `cache_hit=True` no-op rebuild with `draft` staying `False` in build-record.json —
  the common path pays nothing extra. Covered by
  `tests/test_portability.py::test_corrupted_zip_reports_independent_rows`'s added
  `quoin.check.build` patch (needed because check() now calls `build`, whose own
  internal `assemble()` reference isn't the one that test already patched).

- 012's Step 3 hit its own second STOP condition on the real corpus: `corpus/vol2
  check --visual` renders all 26 spine docs cleanly (no open/screenshot failures),
  but three come back genuinely under the 0.2% dark-pixel floor: `movement-m1.xhtml`
  (0.1802%), `movement-m3.xhtml` (0.1916%), `movement-m4.xhtml` (0.1808%). All three
  are movement-divider pages that intentionally render as nothing but a single
  vertically-centered `<h1>` inside `assemble.py`'s `.fullpage` divider template —
  confirmed correctly styled, not broken or blank, via a manual agent-browser
  screenshot of `movement-m1.xhtml`. Per the plan's own Step 3 wording ("fix nothing
  content-side... if a real page fails, report it, that is the check working") and
  its STOP condition ("do not tune the threshold to pass"), this is reported here
  rather than adjusting `INK_RATIO_THRESHOLD` or the corpus content: `ink_ratio`
  genuinely FAILs on `corpus/vol2` today, and so does `check --visual`'s exit code.
  The corpus owner's call, not this plan's: accept the three divider pages as a
  known, by-design gap (e.g. an ink_ratio allowance keyed to single-heading
  `.fullpage` divider content), or give them more visual weight. The plan's first
  STOP condition (agent-browser can't render local `file://` xhtml with the book's
  relative CSS) did not fire — confirmed via smoke test that `../styles/book.css`
  loads correctly with no `--allow-file-access` flag needed. Separately, non-visual
  `alt_text` on `corpus/vol2` now reports clean: the vision-authored `alt_overrides`
  entries the owner merged into `manifest.json` ahead of this plan (replacing 005's
  source-level waiver for the same 29 figures, plus 4 more) supersede that waiver.
